BMC Group Dashboard Guide

How to read and use your monitoring dashboards

Documentation · Updated for live production

Your three dashboards,
explained simply.

BMC Group runs on a connected set of services — the website, Sanity CMS, the Autotrader stock pipeline, and fuel-price sync — plus a Business Insights layer covering stock accuracy and reservation follow-ups. This guide explains what each panel is checking, what good looks like, and what to do when something goes wrong. Panels covering services now monitored elsewhere (Stripe, Resend, CookieYes) or superseded by better checks (the old simple Autotrader reachability check) have been retired from the dashboards themselves — this guide has been updated to match.

Vercel / Website
Status Dashboard ▼
What it does
Checks that the BMC Next.js website is live and reachable. It pings three pages — the homepage, inventory listing, and finance page — to confirm all three are responding correctly. Vercel hosts the website and handles all deployments to it.
Homepage
Main entry point — if this is down the whole site is down
Inventory
Vehicle listings page — most visited page on the site
Finance page
Codeweavers finance embed — critical for finance enquiries
What to look out for
All green — Operational
All three pages are responding. No action needed.
Amber — one page not responding
Check Vercel dashboard for deployment errors. May be a temporary Vercel outage — try refreshing in 2 minutes. If persisting, contact IT Support.
Red — site completely unreachable
Check Vercel status page (vercel.com/status). If Vercel is up but site is down, contact IT Support immediately — a deployment may have broken the site.
🗄
Sanity CMS
Status Dashboard ▼
What it does
Sanity is the content management system that stores all vehicle data, promotions, location information and site settings. The dashboard checks that both the Sanity API (which the website queries for content) and the Sanity Studio (where you manage content) are reachable.
What to look out for
Green — API and Studio both reachable
Content is flowing normally. Vehicle pages, promotions and locations are all live.
Amber — Studio unreachable but API working
The website will still work as it queries the API directly. You won't be able to edit content in the studio until it recovers. Check sanity-status.com.
Red — Sanity API down
The website may show blank vehicle pages or errors. This is a Sanity platform issue — check sanity-status.com and contact Sanity support if it persists beyond 15 minutes.
⛽
Fuel Finder
Status Dashboard ▼
What it does
A Vercel cron job runs every 30 minutes and calls the UK Government Fuel Finder API to get the current petrol and diesel prices at Brooke Garage. It stores the prices in Sanity so they display on the BMC website petrol stations page. The dashboard checks that the Fuel Finder API is reachable and the cron endpoint is live.
What to look out for
Green — prices updating correctly
Fuel prices on the website are current. No action needed.
Amber — intermittent failures
The Government API is unreliable and times out frequently. The prices on the site may be a few hours old. If the site is showing prices that are clearly outdated (more than 24 hours old) check Sanity directly and update manually if needed.
Red — station not found or persistent failure
The Brooke Garage station ID may have changed in the Government feed. Check the Vercel logs. The last known prices will remain on the site until the sync recovers.
Known issue — intermittent failuresThe Government Fuel Finder API has a history of unreliability and frequent timeouts. This is outside BMC's control. Expect to see this card amber from time to time — the last successfully synced prices always remain on the site in the meantime.
🖥
VPS Sync Server
Status Dashboard ▼
What it does
The VPS (Virtual Private Server) is a DigitalOcean server hosted at IP address 159.65.17.84. It runs the bmc-sync script and the reactivation cron, which together keep Sanity matched to Autotrader. Without the VPS the stock on the BMC website would go out of date. This card checks that the server itself is reachable and that DigitalOcean's platform is operational — it does not confirm the sync job actually completed successfully. That is what the batch sync's own Healthchecks.io heartbeat and the Stock Reconciliation card on the Business Insights dashboard are for.
What to look out for
Green — server reachable
The server itself is up. Combine with the Stock Reconciliation card on the Business Insights dashboard to confirm the sync is actually keeping stock current.
Red — server unreachable
The Autotrader sync has almost certainly stopped. Stock will go stale. Check the DigitalOcean dashboard (cloud.digitalocean.com) — the droplet may need restarting.

Stock Reconciliation
Business Insights ▼
What it does
This card replaced the old simple "Autotrader Sync" reachability check. Rather than just confirming the Autotrader API responds, it does something far more useful: it pulls the live Autotrader stock count and the live Sanity active-vehicle count, per advertiser (Brooke 833349 and Norwich 10043362), and confirms they actually match. It also surfaces any currently outstanding failedSync trace documents — vehicles whose last content write to Sanity failed and hasn't yet self-corrected. A scheduled check refreshes this roughly every 15 minutes.
What to look out for
Green — counts match, zero failedSync records
Autotrader and Sanity agree for both Brooke and Norwich. No action needed.
Amber — small count mismatch
A handful of vehicles are out of step, most often a transfer between Brooke and Norwich still working through, or the batch sync's next run hasn't caught it yet. Check the failedSync record list before assuming anything is broken — many mismatches self-correct within the hour.
Red — status file unreachable, or a large/persistent mismatch
If the status file itself can't be loaded, the scheduled reconciliation check has stopped running — check the GitHub Actions workflow run history via the card's link. If the file loads but shows a large or growing mismatch, check the failedSync records for the affected stock IDs, and check whether any vehicle is stuck mid-transfer inside Autotrader's own system (a known limitation — see the Technical Architecture Document, Section 5.3).
Reads from a committed status file, not a live queryThis card doesn't query Autotrader or Sanity directly from the browser — it reads reconcile-status.json, a file the scheduled check commits back to the repository each run. If Netlify is serving a stale cached copy, the card fetches the file from raw.githubusercontent.com directly to guarantee it's current. If this card looks frozen (the timestamp inside the linked JSON isn't advancing), the workflow itself has likely stopped running rather than the site being wrong.

Reservation Alerts
Business Insights ▼
What it does
A staff follow-up list for £99 deposit reservations, built directly from Sanity. Unlike the other cards on either dashboard, this one isn't really a fault indicator — it's a to-do list. It checks three things at once: vehicles whose reservation has already been cleared in the last 24 hours (worth a follow-up call), vehicles whose hold ends today, and vehicles whose hold ends tomorrow.
What each colour means
Red — reservation ended and was cleared in the last 24 hours
The £99 deposit hold has run out and the hourly expiry job has already removed the "Reserved" flag, so the vehicle is showing as available to other customers again. Worth a follow-up call to check whether the original customer still wants it.
Amber — reservation ends today
Still showing as reserved, but the hold expires later today. A good moment to check in with the customer before it lapses.
Green — reservation ends tomorrow
Nothing needs doing yet — this is advance visibility of what's coming up next, not a warning.
Red relies on a dedicated trace recordOnce a reservation expires, the hourly expiry job deletes the customer and deposit details from the vehicle record entirely — otherwise there would be no way to tell "just cleared" apart from "never reserved at all". A small reservationCleared-<vehicleId> record is written first, specifically so this card can still show it for 24 hours afterwards.
💷
Sales by Price Band
Business Insights ▼
What it does
Groups every recorded sale into £2,500 price bands (£0–£2.5k, £2.5k–£5k, and so on), ranked from the highest band down to the lowest. Each band shows how many vehicles sold in that range and the average number of days those vehicles took to sell. This is genuinely informational — not a fault indicator, and it's expected to be sparse or empty for a while after being switched on, since it can only ever show sales that happened after the underlying tracking was added.
What to expect
Always green
This card is only ever red if the query itself fails to load — never for having few or no sales recorded. A quiet card genuinely means "not much sales history yet", not "something's wrong".
Builds up from zeroThere's no way to backfill sales that happened before this tracking existed — every vehicle previously just had isActive flipped to false with nothing else recorded. This card only reflects genuine sales from the day the tracking was switched on, onward. Expect it to look sparse for the first few weeks.
🚗
Sales by Make & Model
Business Insights ▼
What it does
Groups every recorded sale by make and model, ranked from the highest-selling combination down to the lowest, with the average days-to-sell shown for each. Ties (equal sale counts) are broken alphabetically for a stable, predictable order. Same as the price band card, this is purely informational.
What to expect
Always green
Only ever red if the query itself fails — not for having little data. Builds up the same way as the price band card, from zero, starting the day the tracking was switched on.

Website Page Load Speed
Metrics Dashboard ▼
What it does
Measures how quickly the BMC website responds to requests. It times three key pages — Homepage, Inventory and Finance — and shows the fastest, average and slowest response times. The speed bars fill up as response time increases — a shorter bar means a faster page.
What good looks like
Under 400ms — Excellent
Pages are loading very quickly. Customers will have a smooth experience.
400ms–1000ms — Acceptable
Slightly slower than ideal but still within acceptable range. Monitor over time to see if it improves or worsens.
Over 1000ms — Slow
Pages are loading too slowly. This can affect Google search rankings and cause customers to leave before the page loads. Contact IT Support to investigate — may be a Vercel issue or a slow Sanity query.
🗄
Sanity API Response Time
Metrics Dashboard ▼
What it does
Measures how quickly the Sanity CMS responds to content queries. Every vehicle page, promotion and location on the BMC website requires a Sanity API call. The panel also shows your current Sanity usage against the plan limits — API requests, CDN requests and document count.
What to look out for
Under 500ms — Good
Sanity is responding quickly. Vehicle pages will load fast.
API usage approaching plan limit
Consider upgrading the Sanity plan or optimising queries to reduce API calls. Note the website deliberately runs with useCdn: false to avoid stale/inconsistent reads, which trades away some CDN offload and increases metered API usage compared with a CDN-backed setup — so usage naturally runs higher than a typical Sanity site of this size, and should be watched as traffic grows rather than treated as a bug.
🚗
Vehicle Inventory Count
Metrics Dashboard ▼
What it does
Pulls live vehicle counts directly from Sanity. Shows total live stock and a split between Brooke and Norwich branches. This data is live and accurate — it is a direct query, not a simulation.
What to look out for
Count matches your Autotrader portal
If the vehicle count on the dashboard matches what you see in the Autotrader dealer portal, the sync is working correctly. The Stock Reconciliation card on the Business Insights dashboard checks this automatically per advertiser, so it's usually the faster place to confirm this rather than counting by eye here.
Count significantly lower than Autotrader
The Autotrader sync may have stopped, or a batch of vehicles has a dropped content write. Check the Stock Reconciliation card on the Business Insights dashboard and the VPS Sync Server card on IT Service Status.

Fuel Price Sync
Metrics Dashboard ▼
What it does
Shows the current fuel prices stored in Sanity for Brooke Garage (unleaded, premium, diesel) and how reliably the sync is running. The prices shown are pulled live from Sanity so they reflect exactly what the website is displaying to customers.
What to look out for
Prices match the forecourt
The sync is working. Prices on the BMC website match what customers see at the pump.
Prices are outdated or incorrect
You can manually update prices in Sanity Studio (bmc-vehicles.sanity.studio → Locations → Brooke Garage) while the sync issue is investigated. This is a temporary fix.
Government Fuel Finder API reliabilityThis feed has a history of intermittent failures independent of anything in our own code. The last successfully synced prices always remain on the site, so a sync failure does not blank the page — it just means prices may lag until the next successful run.

What's no longer on these dashboards, and why
A few panels that appeared in earlier versions of this guide have since been removed from the live dashboards themselves. This guide has been updated to match — if you're looking for one of these, here's where that monitoring actually lives now:
Stripe Reservations (status & metrics)
A simple "is the Stripe API reachable" check told us nothing about whether payments were actually processing. Real payment and webhook health is monitored directly in the Stripe Dashboard.
Resend Emails (status & metrics)
Same issue — an API reachability check doesn't confirm delivery. Email delivery, bounces and failures are monitored in the Resend Dashboard.
CookieYes
Whether the consent banner is loading and gating tracking correctly is easily checked by visiting the live site directly — a dashboard card added little.
Autotrader Sync (old simple version)
Replaced entirely by the Stock Reconciliation card (now on the Business Insights dashboard), which checks actual stock-count agreement rather than just whether the API responds — a far more meaningful signal.
Enquiry Form Submissions (metrics)
This panel showed simulated data pending a server-side connection that was never built out; it was removed rather than leave a permanently-simulated card in place.
